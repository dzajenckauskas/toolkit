# Architecture Decision Records

Architecture Decision Records document durable product and technical choices.

## Naming

`ADR-XXX-short-description.md`

Example:

`ADR-004-client-side-image-processing.md`

## Status values

- Proposed
- Accepted
- Superseded
- Rejected
- Deprecated

## Template

```md
# ADR-XXX: Decision title

- Status: Proposed
- Date: YYYY-MM-DD

## Context

What problem or uncertainty requires a decision?

## Decision

What was decided?

## Consequences

What becomes easier, harder, possible, or restricted?

## Alternatives considered

What credible options were rejected, and why?
```

Create an ADR when a decision affects architecture, scope, user experience, security, privacy, costs, or future implementation choices.
