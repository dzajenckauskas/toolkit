# Product Principles

## 1. Start with the task

The interface should begin with the user's immediate action, usually adding an image. Do not begin with account creation, onboarding questionnaires, or project setup.

## 2. Simple first, powerful second

The default path should require very few decisions. Advanced controls can exist, but should not dominate the interface.

## 3. Standalone tools must be complete

A tool should not feel like a disabled fragment of a larger suite. It must solve its named task well.

## 4. Projects are optional

Projects exist to save settings and repeat workflows. They are not required for casual use.

## 5. Results must be understandable

Show meaningful before-and-after information such as dimensions, format, quality, and file size.

## 6. Preserve user trust

Explain whether images remain on the device, are uploaded temporarily, or are retained. Never make privacy claims that the implementation cannot support.

## 7. Avoid premature platforms

Do not build a complex shared workflow engine before the individual tools reveal what should actually be shared.

## 8. Ecommerce relevance

Generic image features should be expressed through ecommerce use cases, presets, terminology, and practical export defaults.
