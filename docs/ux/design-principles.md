# UX and Design Principles

## Primary flow

The first visible action should be adding an image.

Recommended sequence:

1. Add images
2. See previews and detected information
3. Adjust a small number of relevant settings
4. Process automatically or with one clear action
5. Compare results
6. Download

## Layout

Desktop may use a split or multi-column layout, but mobile should remain a clear vertical sequence.

Suggested regions:

- Tool title and concise purpose
- Upload area
- File queue
- Settings
- Results and downloads
- Privacy explanation

## Interaction rules

- Do not hide the primary download action.
- Keep destructive actions visually distinct.
- Allow removal and retry per file.
- Preserve settings when users add more files.
- Make batch state understandable.
- Use human-readable file sizes.
- Never imply that quality is unchanged after lossy compression.

## Empty states

Empty states should instruct through action, not paragraphs.

Example:

> Drop product images here, paste from your clipboard, or choose files.

## Error messages

Messages should explain:

- What failed
- Which image was affected
- Whether other files can continue
- What the user can do next

## Accessibility

- Keyboard-accessible upload and controls
- Visible focus states
- Proper labels for sliders and numeric fields
- Status announcements for processing
- Do not rely on color alone
- Adequate contrast
- Touch-friendly targets

## Visual direction

The product should feel calm, capable, modern, and practical. Avoid ad-like clutter, exaggerated gradients, and excessive dashboard chrome.
